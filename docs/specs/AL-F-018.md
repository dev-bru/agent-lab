   `COM1`), keeps the path `<docs_dir>/<name>.md` inside `docs_dir` (resolved), and returns the file text (UTF-8).
   A bad name gives an error whose text names the rule; a missing file gives an error `no doc named '<name>'`. Use
   FastMCP's resource error type (`fastmcp.exceptions.ResourceError`) so the client sees the message. Reuse one
   small helper for the name check shared with `_note_path` instead of copying the regex and device list (keep
   `_note_path`'s messages and behaviour the same).
