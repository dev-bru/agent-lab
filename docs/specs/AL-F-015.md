## Acceptance criteria
1. **`model.model_error(error, settings=None) -> ModelError | None`** (new, in `model.py`):
   - if `"litellm"` is not in `sys.modules`, return `None` at once (the error cannot come from LiteLLM, and importing
     it would cost 8 s);
   - otherwise check the error with `isinstance` in this order: `litellm.Timeout`, then
     `litellm.APIConnectionError`/`litellm.InternalServerError`, then `litellm.BadRequestError`. Call
     `settings_module.load()` only inside the `Timeout` and server-down branches, and only when `settings is None`,
     so a `ValueError` or `ScriptExhausted` passing through never reads settings. Map exactly as `chat()` does today:
     - `litellm.Timeout` -> `ModelTimeout("model did not answer within <timeout_s> s (timeout_s)")`;
     - `litellm.APIConnectionError`, or `litellm.InternalServerError` while `model_server.port_in_use(settings)` is
       false -> `ModelServerDown("cannot reach the model at <host>:<port>; run: agent-lab model start")`;
     - any other `litellm.InternalServerError`, and `litellm.BadRequestError` -> `ModelError(str(error))`;
     - anything else -> `None`.
   - `chat()` uses it: `except Exception as error:` around `litellm.completion`, then `mapped = model_error(error,
     settings)`; `raise mapped from error` when it is not `None`, else `raise`. Behaviour and messages stay the same,
     and all existing `test_model.py` tests pass unchanged.
2. **`graph.run`**: in its `except Exception as error:` branch, `mapped = model_module.model_error(error)`; the
   `error` trace record uses `str(mapped if mapped is not None else error)`; then `raise mapped from error` when not `None`, else `raise`.
   Round 2: `graph.chat_model()` also does `import litellm` and `litellm.suppress_debug_info = True` right after
   its `ChatLiteLLM` import (MEASURED: without it, a no-server graph chat prints LiteLLM's "Give Feedback / Get
   Help" banner). Nothing else in `graph.py` changes.
3. **`cli.py`**: `agent-lab chat [--engine hand|graph] [--fake [SCRIPT]]` (default engine `hand`;
   `--fake` const `fakes.builtin("chat")`: `--fake` alone uses the built-in script, `--fake PATH` uses PATH; argparse
   `choices` refuses another engine with exit 2). The `chat` subparser help is `Chat with the local model. Each
   line is a new agent run with no memory of earlier lines.` The `model` command is unchanged. Remove the "Not built
   yet" branch. `cli.py` does `from agent_lab import mcp_client` and calls `mcp_client.McpTools(...)` (tests patch
   it). `chat` does:
   1. `config = settings.load()`; when `--fake` is not given, call `model_server.check_host(config)` for both
      engines (the graph engine has no other host check; `ModelServerError` gives exit 1). Build the chat model:
      hand uses `fakes.FakeModel(script)` with `--fake`, else the
      `model` module; graph uses `fakes.FakeChatModel(script)` with `--fake`, else `graph.chat_model(config)`. The
      run function is `hand.run` or `graph.run`;
   2. `with mcp_client.McpTools(settings=config) as tools:` loop:
      - `line = input("you> ")`; `EOFError` ends the loop;
      - strip the line; skip an empty line; `exit` ends the loop;
      - `with trace.Trace.new(config.runs_dir, <engine>) as log:` run the agent with `trace=log`, `echo=print`;
      - print `agent> ` plus `result.text`, then `[trace] ` plus `log.path`;
   3. return 0.
   - One `try` wraps all of step 1 and step 2, including `settings.load()`, building the model, `McpTools(...)` and
     the loop. `KeyboardInterrupt` is caught outside the `with McpTools` block, so the block closes first. Errors
     print to stderr with no traceback (catch `ModelServerDown` before `ModelError`):
     - `model.ModelServerDown` -> `error: ` plus the message, return 2;
     - `fakes.ScriptExhausted` -> `error: the fake script has no more replies`, return 1;
     - `model.ModelError`, `model_server.ModelServerError`, `settings.SettingsError`, `mcp_client.McpError`,
       `OSError`, `ValueError`, `ImportError` -> `error: ` plus the message, return 1;
     - `KeyboardInterrupt` -> print an empty line, return 0. The `with` block has closed `McpTools` by then.
   - Every function, including nested ones, has a docstring with no sentence over 20 words
     (`tests/test_docstrings.py` and `tests/test_model_server.py::test_module_docstrings_and_local_urls` check
     `cli.py`); plain teaching comments.
4. **`fake_scripts/chat.json`**: the three replies of `two_tool.json`, then `{"text": "You are welcome."}`.
5. **Tests.** No network except refused connections to `127.0.0.1`. Every new test function has a docstring.
   - `tests/test_cli.py`: subprocess `[sys.executable, "-m", "agent_lab.cli", "chat", ...]` with `cwd=ROOT`,
     `PYTHONPATH=src`, `PYTHONUTF8=1`, utf-8, `timeout=120`, `AGENT_LAB_NOTES_DIR` and `AGENT_LAB_RUNS_DIR` in
     `tmp_path`, and stdin text. Script files are written to `tmp_path` (UTF-8, LF) and passed as `--fake` plus the
     path. Answers are checked on stdout and errors on stderr. The `you> ` prompt has no newline and joins the next
     echo line, so checks use `splitlines()` and `startswith("agent> ")`, never a whole-output match:
     - **REQ-040 AC1**, for `--engine hand` and `--engine graph` (parametrized), args `--fake`, stdin
       `What is 17 times 23? Save the answer as a note called result.\n\nthanks\nexit\n`: exit 0; exactly two
       `agent> ` lines, the first containing `391`, the second equal to `agent> You are welcome.`; two `[trace] `
       lines; two `*-<engine>.jsonl` files in the runs folder; no `Traceback`;
     - for both engines (parametrized): end of input without `exit` (stdin `thanks\n` with a script file
       `[{"text": "ok"}]`) exits 0;
     - for both engines (parametrized): no `--fake`, env `AGENT_LAB_HOST=example.com`, stdin `hi\n`: exit 1; stderr
       contains `host must be 127.0.0.1 or localhost`; no `Traceback`;
     - `--fake` with a path that does not exist exits 1 with stderr containing `error: invalid script path`;
     - `chat --help` output contains `new agent run`;
     - **REQ-040 AC2**, for both engines (parametrized), no `--fake`, env `AGENT_LAB_HOST=127.0.0.1` and
       `AGENT_LAB_PORT=<a free port>` (bind a socket to port 0, read the port, close it), stdin `hi\n`: exit 2;
       stderr contains `cannot reach the model at 127.0.0.1:<port>` and `agent-lab model start`; no `Traceback`;
       round 2: stdout and stderr contain neither `Give Feedback` nor `LiteLLM.Info`;
     - for both engines (parametrized): an empty script file `[]` with stdin `hi\n` exits 1 with
       `error: the fake script has no more replies`;
     - **REQ-040 AC3**, in-process: `monkeypatch` the env folders and `builtins.input` to raise
       `KeyboardInterrupt`; wrap `cli.mcp_client.McpTools` with a subclass that records each instance;
       (`monkeypatch.setattr(cli.mcp_client, "McpTools", Recording)`); `cli.main(["chat", "--fake"])` returns 0,
       and the recorded instance's thread is not alive. Then: `before = _server_pids()`, run a subprocess AC1 run,
       and poll up to 5 s until `_server_pids() - before` is empty; fail if it is still not empty. Copy the
       CIM-with-fallback `_server_pids` helper from `tests/test_mcp_client.py` into `test_cli.py` (do not import
       across test files).
   - `tests/test_model.py` (add, do not change existing tests): `model_error(ValueError("x"), S) is None`;
     `litellm.Timeout(...)` -> `ModelTimeout`; `litellm.InternalServerError("Connection error.", ...)` with the port
     check patched to false -> `ModelServerDown` whose text names `127.0.0.1:9999`.
   - `tests/test_agent_graph.py` (add): a stub chat model (`bind_tools` returns itself; `invoke` raises
     `litellm.InternalServerError("Connection error.", llm_provider="openai", model="m")`), env pointing to a free
     port: `graph.run` raises `model.ModelServerDown`, and the trace's `error` record names the host and port.
6. **Full suite.** `.venv\Scripts\python.exe -m pytest -rs -W error::DeprecationWarning` passes with 0 skipped; the
