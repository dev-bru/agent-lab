## Goal
A learner sees one full tool call: the program offers a tool, the model asks for it, the program runs it and sends
the result back with the same id, and the model answers. The small bridge module is reused by the agents later.

## Acceptance criteria
1. **`tools_schema.to_openai(tool) -> dict`.** It takes an object with `.name`, `.description` and `.input_schema`
   (fastmcp 4.1.4 field names; never the deprecated `inputSchema`). It returns `{"type": "function", "function":
   {"name": tool.name, "description": tool.description or "", "parameters": tool.input_schema}}`, using the schema
   object as is.
2. **`tools_schema.check_args(schema: dict, args) -> list[str]`** returns problems; `[]` means valid.
   - `args` not a `dict` returns `["arguments must be a JSON object"]` at once.
   - Then, in this order:
     1. one `missing argument '<name>'` for each name in `schema.get("required", [])` that is absent, in that
        list's order;
     2. one `unknown argument '<name>'` for each key in `args` (in `args` order) that is not in
        `schema.get("properties", {})`. Unknown keys are never type-checked;
     3. one type problem for each known key in `args` (in `args` order) whose property has a `type` that does not
        match:
        - `string` -> `str`;
        - `number` -> `int` or `float`, not `bool`;
        - `integer` -> `int`, not `bool`;
        - `boolean` -> `bool`;
        - `object` -> `dict`;
        - `array` -> `list`;
        - `null` -> `None`.

        The message is `argument '<name>' must be <schema type>, got <type(value).__name__>`, for example
        `argument 'a' must be number, got str`, `argument 'a' must be number, got bool` and
        `argument 'n' must be integer, got float`.
   - A property with no `type`, a type list or another type is not checked (`ponytail:` comment: only the types
     the 9 tools use).
3. **Fake script** `src/agent_lab/fake_scripts/02_tool_call.json`, exactly:
   `[{"tool_calls": [{"name": "multiply", "arguments": "{\"a\": 17, \"b\": 23}"}]}, {"text": "17 times 23 is
   391."}]`
4. **Lesson** `lessons/02_tool_call.py`, runnable alone.
   - It has a module docstring of 2 to 4 short sentences (checked in review). Every function, including
     `multiply`, `run` and `main`, has a docstring with at most 20 words per sentence (`tests/test_docstrings.py`).
     There is a plain comment before each step.
   - It imports `agent_lab` (`fakes`, `model`, `model_server`, `settings`, `tools_schema`) and the standard
     library.
   - It defines a local `multiply(a, b)` and its schema `MULTIPLY`: `{"type": "function", "function": {"name":
     "multiply", "description": "Multiply two numbers. Give a and b as numbers.", "parameters": {"type": "object",
     "properties": {"a": {"type": "number"}, "b": {"type": "number"}}, "required": ["a", "b"]}}}`.
   - `show(x)` formats a number: `str(int(x))` when `x` is a float with `x.is_integer()`, else `str(x)`. So 391.0
     prints `391`, and `inf`/`nan` print as Python does.
   - `run(chat) -> int` does the steps below. `main(argv=None) -> int` parses `--fake [SCRIPT]` (as lesson 01,
     built-in script `02_tool_call`) and calls `run` with `FakeModel(script).chat` or `model.chat`. Steps:
     1. `messages = [{"role": "system", "content": "You are a helpful assistant. Use tools when they help."},
        {"role": "user", "content": "What is 17 times 23? Use the multiply tool."}]`, then print `you> <question>`;
     2. `reply = chat(messages, tools=[MULTIPLY])`;
     3. if `reply.tool_calls` is empty, print `agent> <text>`, then `the model answered without a tool`, and
        return 0;
     4. append the assistant message `{"role": "assistant", "content": reply.text or "", "tool_calls":
        [{"id": c.id, "type": "function", "function": {"name": c.name, "arguments": c.arguments}} for c in
        reply.tool_calls]}`;
     5. for each call in order, print the request line `agent> tool call <name> <arguments>`. Then decide the
        result, checking in this order:
        1. `json.loads(arguments)`; on failure the problem is `arguments are not valid JSON`;
        2. a name other than `multiply` gives `unknown tool '<name>'; valid tools: multiply`;
        3. `tools_schema.check_args(MULTIPLY["function"]["parameters"], args)` (a non-dict gives the object
           message).

        With no problems, print the result line `[tool: multiply] <show(multiply(**args))>` and use that text as
        the content. With problems, print `[tool: <name>] error: <problems joined with "; ">` and use that text.
        Append `{"role": "tool", "tool_call_id": c.id, "content": <content>}`. All calls are answered before the
        next step;
     6. `final = chat(messages, tools=[MULTIPLY])`, then print `agent> <final.text>`. If `final.tool_calls` is not
        empty, also print `the model asked for another tool; this lesson stops here`.
   - Errors, as in lesson 01, print to stderr and return 1, with no traceback:
     - the `ModelError` family, `ModelServerError`, `SettingsError` and `ValueError` print `error: <message>`;
     - `fakes.ScriptExhausted` prints `error: the fake script has no more replies`.
5. **Tests:**
   - `tests/test_tools_schema.py`:
     - `to_openai` on all 9 tools of the real server (in-memory `Client(mcp_server.mcp).list_tools()`):
       - each result has type `function`, the tool's name and description, and `parameters is tool.input_schema`;
       - for `multiply`, `parameters["required"] == ["a", "b"]`;
     - a stub object with `description=None` gives `""`;
     - `check_args` with `S = {"type": "object", "properties": {"a": {"type": "number"}, "b": {"type":
       "integer"}, "c": {}}, "required": ["a", "b"]}`:
       - `{"a": 1.5, "b": 2}` gives `[]`, and `{"a": 1, "b": 2, "c": "anything"}` gives `[]`;
       - `{"c": 1, "d": 2}` gives `["missing argument 'a'", "missing argument 'b'", "unknown argument 'd'"]`;
       - `{"a": "x", "b": 2}` gives the `got str` message, and `{"a": True, "b": 2}` the `got bool` message;
       - `b` set to `1.5` gives `must be integer, got float`, and `True` gives `got bool`;
       - `5` and `[1]` give `["arguments must be a JSON object"]`.
   - `tests/test_lesson_02.py` (`ROOT`; subprocess as in lesson 01's test, with `cwd=ROOT`, `PYTHONPATH=src`,
     utf-8 and `timeout=60`; custom scripts written to `tmp_path`):
     - `--fake`: exit 0; stdout contains `agent> tool call multiply`, `[tool: multiply] 391` and
       `agent> 17 times 23 is 391.`;
     - in-process (REQ-011 AC2):
       - load the module with `spec_from_file_location("lesson_02", ROOT / "lessons" / "02_tool_call.py")`,
         `module_from_spec` and `exec_module`;
       - call `run(fake.chat)` with `fake = fakes.FakeModel(fakes.builtin("02_tool_call"))`;
       - expect `len(fake.requests) == 2`. The second request's messages hold a `tool` message with
         `tool_call_id == "call_1"`, and the assistant message before it has a tool call with id `call_1`;
     - a two-reply script, a call `{"a": "x", "b": 2}` then `{"text": "ok"}`, prints
       `[tool: multiply] error: argument 'a' must be number, got str` and exits 0;
     - a one-text script prints `the model answered without a tool` and exits 0;
     - an empty script (`[]`) exits 1. Stderr contains `error: the fake script has no more replies` and no
       `Traceback`;
     - the lesson and `tools_schema.py` sources contain no `http://` or `https://`.
6. **Full suite.** `.venv\Scripts\python.exe -m pytest -rs -W error::DeprecationWarning` passes, with 0 skipped.
   The test count is at least 98 (the last verified run) plus the new test functions.
