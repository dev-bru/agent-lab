## Goal
Agent Lab gets its own MCP server. This first part has five small tools a model can call: add, multiply, unit
conversion, the current time in a zone, and the days between two dates. Bad input gives a clear error result
that a small model can read and fix.

## Facts
- MEASURED 2026-10-30 (venv import): FastMCP 4.1.4 exports `FastMCP` and `Client`. `ToolError` is in
  `fastmcp.exceptions`. `Client.call_tool(name, arguments, *, raise_on_error=True)` returns a `CallToolResult`.
- DOCUMENTED (fastmcp 4.1.4 source, read 2026-10-30 by the spec auditor):
  - `@mcp.tool` returns a `FunctionTool`, so the decorated name is NOT callable. Tests must go through `Client`.
  - `result.data` holds the typed return value (float, int or str).
  - With `raise_on_error=False`, an error gives `is_error=True`, `data=None`, and the `ToolError` text in
    `content[0].text`.
  - The in-memory `Client(server)` uses anyio streams with no network sockets.
  - `tzdata` provides `Asia/Kolkata` on Windows.

## Round 2 change (orchestrator stdio check, 2026-10-30)
DOCUMENTED (fastmcp 4.1.4 source: `server/mixins/transport.py` calls `utilities/cli.log_server_banner`, which calls

- `main()` calls `mcp.run(show_banner=False)`.
- Tests (add to `tests/test_tools_math_time.py`):

  - run `[sys.executable, "-m", "agent_lab.mcp_server"]` with `stdin=subprocess.DEVNULL`, `capture_output=True`,
    `encoding="utf-8"`, `errors="replace"`, `timeout=60` and `env={**os.environ, "PYTHONPATH": str(ROOT / "src")}`.
    Expect exit 0, and stderr without `Traceback` and without `http`.

## Acceptance criteria
1. **Server.** `mcp = FastMCP("agent-lab")` at module level. `main()` calls `mcp.run()` (stdio by default).
   `if __name__ == "__main__": main()`. The module does no other work at import.
2. **Docstrings (REQ-052).** The module, `main` and each of the five tool functions have docstrings. A tool's
   docstring is the description the model sees. It has one or two plain sentences that say what the tool does
   and the input format, with at most 20 words per sentence (the existing `tests/test_docstrings.py` checks this).
3. **Tools,** each registered with `@mcp.tool`:
   - `add(a: float, b: float) -> float` and `multiply(a: float, b: float) -> float`. `nan` and `inf` are allowed
     and not tested.
   - `convert_units(value: float, from_unit: str, to_unit: str) -> float`:
     - Kinds and factors to the base unit:
       - `length` (metres): `mm` 0.001, `cm` 0.01, `m` 1, `km` 1000, `in` 0.0254, `ft` 0.3048, `mi` 1609.344;
       - `mass` (kilograms): `g` 0.001, `kg` 1, `lb` 0.45359237;
       - `temperature` (Celsius): `C` as is, `F` -> C by `(F - 32) * 5 / 9`, `K` -> C by `K - 273.15`, and the
         reverse formulas back.
     - Convert to the base unit, then to the target, then `round(x, 6)`.
     - Unit names are exact (case-sensitive). `from_unit == to_unit` is allowed.
   - `now(timezone: str = "UTC") -> str` returns `datetime.now(ZoneInfo(timezone)).isoformat(timespec="seconds")`.
   - `days_between(start: str, end: str) -> int` checks `start` first, then `end`. Each must pass
     `re.fullmatch(r"\d{4}-\d{2}-\d{2}", s, re.ASCII)` and `date.fromisoformat` (its `ValueError` is caught). It
     returns `(end - start).days`.
4. **Errors** raise `ToolError` with these exact texts:
   - Unknown unit: `unknown unit '<u>'; valid units: mm, cm, m, km, in, ft, mi, g, kg, lb, C, F, K`. `from_unit`
     is checked first, then `to_unit`.
   - Different kinds: `cannot convert <from> (<kind>) to <to> (<kind>); valid <from kind> units: <units of that
     kind>`. Units are comma-space separated in the order above.
   - Bad zone (`ZoneInfoNotFoundError` or `ValueError`, for example `Mars/Base`, `../x` or an empty string):
     `unknown time zone '<z>'; use an IANA name such as Asia/Kolkata or UTC`.
   - Bad date: `dates must be YYYY-MM-DD, got '<first invalid value>'`.
5. **Local only (REQ-053).** The module has no network code. The test asserts that the module source contains no
   `http://` or `https://`.
6. **Tests** (`tests/test_tools_math_time.py`, pytest). Use `asyncio.run` with the in-memory
   `Client(mcp_server.mcp)` from plain sync test functions (no async plugin, no direct calls to the tool names).
   Values come from `result.data`. Errors use `raise_on_error=False`, `result.is_error` and `content[0].text`.
   Cover:
   - the five names are a subset of the `list_tools` names (F-006 and F-007 add more);
   - `multiply(17, 23) == 391`, `add(2, 3.5) == 5.5` and `multiply(-2, 0) == 0`;
   - conversions:
     - `1 mi -> km == 1.609344`, `0 C -> F == 32`, `32 F -> C == 0`;
     - `100 C -> K == 373.15`, `0 K -> C == -273.15`, `1 lb -> kg == 0.453592`, `5 m -> m == 5`;
   - unit errors:
     - `parsec`: the text contains `unknown unit 'parsec'` and all 13 unit names;
     - `km -> kg`: the text contains `km (length)`, `kg (mass)` and `mm, cm, m, km, in, ft, mi`;
     - `KM -> m` is an error;
   - dates:
     - `days_between("2026-10-29", "2026-12-31") == 63`, the reverse gives `-63`, and the same date gives `0`;
     - `2026-02-30` and `29-10-2026` give errors containing `YYYY-MM-DD` and the bad value;
   - time zones:
     - `now("Asia/Kolkata")` ends with `+05:30` and parses with `datetime.fromisoformat`;
     - `now()` with no argument ends with `+00:00`;
     - `Mars/Base` and `../x` give errors containing `IANA`;
   - the source contains no URL (AC5).
7. **Full suite.** `.venv\Scripts\python.exe -m pytest -rs` passes, with 0 skipped. That includes the existing
   docstring test.
