## Acceptance criteria
1. **Parallel by default.** In `pyproject.toml`, `addopts` becomes `"-m 'not live' -n auto"`.
2. **One helper.** Move `_server_pids` to `tests/procs.py` as `server_pids()` (module and function docstrings) and
   import it in both test files (`from procs import server_pids`; pytest puts `tests/` on `sys.path` with the
   default rootdir import mode; if not, say so and use the working option). Delete both old copies. The call
   sites keep their logic.
3. **Own processes only.** `server_pids()` uses one CIM query that returns `ProcessId`, `ParentProcessId` and
   `CommandLine` for all processes (output as JSON with `ConvertTo-Json`; handle a single object and an empty
   result). It returns the PIDs of processes whose command line contains `agent_lab.mcp_server` and that either:
   - are descendants of this test process (`os.getpid()`; walk the parent links of all processes), or
   - are orphans: their parent PID is not a running process.
   A leaked server is one of the two; a server another worker still uses has a live parent outside this tree.
   Add a short comment saying this. Round 2 fix: Windows reuses PIDs, so parent links can form a cycle; the walk
   up the parents must stop at a PID it has already seen (a `seen` set), so it always ends. Also use the plain
   string `"agent_lab.mcp_server"` (round 1 split it in two). Keep the existing fallback (CIM denied in the sandbox: all Python PIDs) with
   its `ponytail:` comment.
4. **Live tests stay serial.** They share one model server. Every documented live command gets `-n 0`:
   `README.md` line ~35, `docs/PRODUCT_SPEC.md` line ~29, `docs/REQUIREMENTS.md` REQ-051 (line ~212):
   `uv run pytest -m live -n 0`. Do not change other requirement text.
5. Run only the test command below (`-n 0`: the sandbox fallback compares all Python PIDs, so it must run
   serially). The orchestrator runs the full suite in parallel: 0 skipped, at least 191 passed (MEASURED after
   AL-T-004), and records the time.
