## Goal
A learner sees how to get data, not prose, from a model: describe the shape with a schema, check the reply, and
when it is wrong, tell the model what was wrong and let it try once more.

## Facts (MEASURED 2026-10-30, Qwen3-1.7B-Q8_0, llama-server build 11408, through `model.chat`)
- With `response_format={"type": "json_schema", "json_schema": {"name": "StudyCard", "schema":
  StudyCard.model_json_schema(), "strict": True}}`, 2 of 2 replies were valid `StudyCard` JSON (2-3 s).
- Without `response_format`, 2 of 2 replies were JSON with an invented `definition` field, so they were invalid.

## Acceptance criteria
1. **Lesson** `lessons/03_structured_output.py`, runnable alone.
   - It has a module docstring of 2 to 4 short sentences (review). Every function has a docstring with at most
     20 words per sentence (`tests/test_docstrings.py`). There is a plain comment before each step.
   - It imports `pydantic` (`BaseModel`, `Field`, `ValidationError`), `agent_lab` (`fakes`, `model`,
     `model_server`, `settings`) and the standard library.
   - `class StudyCard(BaseModel)` with `term: str`, `meaning: str = Field(max_length=200)` and `example: str`, plus
     a docstring.
   - `RESPONSE_FORMAT = {"type": "json_schema", "json_schema": {"name": "StudyCard", "schema":
     StudyCard.model_json_schema(), "strict": True}}`.
   - `describe(error: ValidationError) -> str` returns
     `"; ".join(f"{'.'.join(str(p) for p in e['loc']) or 'reply'}: {e['msg']}" for e in error.errors())`.
   - `run(chat) -> int` and `main(argv=None) -> int` (`--fake [SCRIPT]`, built-in `03_structured_output`, as in
     lessons 01 and 02). Steps:
     1. `messages = [{"role": "system", "content": "You make study cards. Reply with JSON only."}, {"role":
        "user", "content": "Make a study card for the term 'tool calling'."}]`, then print `you> <question>`;
     2. for `attempt` in 1 and 2:
        - `reply = chat(messages, response_format=RESPONSE_FORMAT)`;
        - `text = reply.text or ""`, then print `agent> <text>`;
        - try `StudyCard.model_validate_json(text)`. On success print `[check] valid study card`, then
          `term: <term>`, `meaning: <meaning>` and `example: <example>`, and return 0;
        - on `ValidationError` set `fixes = describe(error)` (do not reuse the name `describe`), then print
          `[check] not valid: <fixes>`;
        - after attempt 1, append `{"role": "assistant", "content": text}` and `{"role": "user", "content": "That
          reply was not a valid study card. Fix these problems and reply with JSON only: <fixes>"}`;
     3. after two failures, print to stderr `error: the reply was not a valid study card after 2 tries: <fixes>`
        and return 1.
   - Other errors use the same `except` tuple and messages as lesson 02. They print to stderr and return 1, with
     no traceback:
     - the `ModelError` family, `ModelServerError`, `SettingsError` and `ValueError`;
     - `ScriptExhausted`, as `error: the fake script has no more replies`.

     `ValidationError` is caught inside the loop first.
2. **Fake script** `src/agent_lab/fake_scripts/03_structured_output.json`, two text replies:
   1. bad: `{"term": "tool calling", "definition": "Using a tool."}`;
   2. good: `{"term": "tool calling", "meaning": "The model asks the program to run a tool.", "example": "The model
      asks for multiply with 17 and 23."}`.

   Both are JSON strings inside `{"text": ...}`.
3. **Tests** (`tests/test_lesson_03.py`; subprocess as in lesson 01/02 tests, with `cwd=ROOT`, `PYTHONPATH=src`,
   utf-8 and `timeout=60`; in-process loading via `spec_from_file_location("lesson_03", ...)` as in
   `test_lesson_02.py`; custom scripts in `tmp_path`). Cover:
   - REQ-012 AC1:
     - `--fake` (built-in, bad then good) exits 0;
     - stdout contains `[check] not valid: meaning: Field required; example: Field required`,
       `[check] valid study card` and `term: tool calling`;
     - in-process with the built-in script, `run(fake.chat) == 0` and `len(fake.requests) == 2`;
     - both requests have `response_format == RESPONSE_FORMAT`;
     - the second request's last message is a user message starting `That reply was not a valid study card.`
       that contains `meaning`;
   - REQ-012 AC2: a script with the built-in bad reply twice exits 1. Stderr contains `error: the reply was not a
     valid study card after 2 tries:`. In-process, `len(fake.requests) == 2`;
   - a script whose first reply has a `meaning` of 201 `x` characters, then the good reply, exits 0. Stdout
     contains `[check] not valid: meaning: String should have at most 200 characters`;
   - a script `{"text": "hello"}` then the good reply exits 0. Stdout contains `[check] not valid: reply: Invalid
     JSON`;
   - a script `{"text": ""}` then the good reply exits 0. Stdout contains `[check] not valid: reply: Invalid
     JSON`;
   - an empty script exits 1 with `error: the fake script has no more replies` and no `Traceback`;
   - the lesson source has no `http://` or `https://`.
4. **Full suite.** `.venv\Scripts\python.exe -m pytest -rs -W error::DeprecationWarning` passes, with 0 skipped and
   at least 112 (MEASURED: the full run after F-009 passed 112) plus the new test functions. `test_docstrings.py`
   and the other lesson tests are not edited.
