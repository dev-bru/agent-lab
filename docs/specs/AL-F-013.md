## Goal
The same agent as `agent.hand`, built the industry way with LangGraph, so a learner can compare the two: the graph
is `START -> model -> tools_condition -> (tools | END)`, `tools -> model`. Fake runs of both agents give the same
tool sequence, final text and trace kinds.

## Facts (MEASURED 2026-10-31, langchain-core 1.7.3, langgraph 1.2.18, in this venv)
- `StructuredTool.from_function(func=f, name=..., description=..., args_schema=<JSON-schema dict>)` does not check
  arguments: `invoke({"x": 1, "b": "s"})` called `f(x=1, b="s")`. So the adapter must call `check_args` itself.
- `ToolNode` answers an unknown tool itself with the text `Error: divide is not a valid tool, try one of
  [multiply].` and runs the other calls of the same message.
- With `stream_mode="updates"`, each update is `{"model": {"messages": [AIMessage]}}` or `{"tools": {"messages":
  [ToolMessage, ...]}}` (one ToolMessage per call, in call order, `tool_call_id` = the call id).
- An always-tool model with `recursion_limit=12` gives 6 `model` and 6 `tools` updates, then
  `GraphRecursionError`.
- `ChatLiteLLM` has the fields `model`, `api_base`, `request_timeout`, `max_retries`, `temperature` and
  `model_kwargs`. Whether `model_kwargs` passes `extra_body` and `api_key` to LiteLLM is UNVERIFIED; the
  orchestrator checks it live after the build.

## Acceptance criteria
1. **`agent_lab.agent.graph`**. The module docstring is short (at most 6 sentences) and names the known differences
   from `hand`:
   - LangGraph writes its own unknown-tool text;
   - invalid JSON arguments from a real model end the run;
   - the trace's `tool_call.arguments` is `json.dumps(args)`, not the model's raw string;
   - `model_request` has `step` only, without the message count;
   - `is_error` is read from the ToolMessage (see below), not from the MCP flag.

   Every function has a docstring (`tests/test_docstrings.py`) and each part has a short teaching comment.
   - Imports: `from agent_lab import model as model_module, settings, tools_schema` (importing `model` sets the
     LiteLLM environment for local calls), plus `McpTools` types as needed. Do not edit `model.py`.
   - `chat_model(config=None) -> ChatLiteLLM`: `config = config or settings.load()`; returns
     `ChatLiteLLM(model=f"openai/{config.model_name}", api_base=urlunsplit(("http", f"{config.host}:{config.port}",
     "/v1", "", "")), request_timeout=config.timeout_s, max_retries=0, model_kwargs={"api_key": "local",
     "extra_body": {"chat_template_kwargs": {"enable_thinking": False}}})`, the same URL rule as `model.py`.
   - `as_langchain_tools(mcp_tools) -> list[StructuredTool]`: one tool per item of `mcp_tools.specs()`, with
     `name`, `description` and `args_schema` (the `parameters` dict) from that spec. Each tool's function takes
     `**args` and:
     1. `problems = tools_schema.check_args(schema, args)`; with problems it returns
        `"error: " + "; ".join(problems)`;
     2. otherwise `text, is_error = mcp_tools.call(name, args)` and it returns `"error: " + text` when `is_error`,
        else `text`.

     Bind `name` and `schema` per tool (a small factory function), so no closure reads a loop variable late.
   - `build(chat_model, tools)` returns a compiled `StateGraph(MessagesState)`:
     - node `model`: `{"messages": [bound.invoke(state["messages"])]}`, where `bound = chat_model.bind_tools(tools)`
       is made once in `build`;
     - node `tools`: `ToolNode(tools)` with default arguments. Do not set `handle_tool_errors`: the default catches
       only argument-validation errors, so an `McpError` from the tool function leaves the graph (MEASURED in
       `langgraph/prebuilt/tool_node.py`), and the unknown-tool text stays as measured;
     - edges `START -> model`, conditional `model -> tools_condition`, `tools -> model`.
   - `run(question, *, model, tools, trace=None, max_steps=6, echo=None) -> RunResult` (same signature as
     `hand.run`; `model` is a LangChain chat model, `tools` an open `McpTools`):
     - `max_steps < 1` raises `ValueError`; `run()` never closes `trace`;
     - the input is `[SystemMessage(SYSTEM_PROMPT), HumanMessage(question)]`; trace `user` with `text`;
     - stream with `{"recursion_limit": 2 * max_steps}` and `stream_mode="updates"`. For each update, in order:
       - echo `[node: <name>]` for `model` and `tools`;
       - a `model` update is step `n` (count them from 1): `text = message.content if isinstance(message.content,
         str) else ""`. Trace `model_request` with `step`, then `model_reply` with `text` and `tool_calls` as
         `[{id, name, arguments}]`, where `arguments` is `json.dumps(args)`. With no tool calls, also trace
         `final` with `text`; the answer is `text`;
       - a `tools` update: for each ToolMessage, find the call of the last model reply with
         `call["id"] == message.tool_call_id`. Trace `tool_call` (`id`, `name`, `arguments` as above), then
         `tool_result` with `id`, `name`, `content` and `is_error = message.status == "error" or
         content.startswith("error: ")` (a teaching comment says this is read from the text, because our tool
         function returns the error as text). Echo `[tool: <name>] <content>`;
     - after the stream: `RunResult(<answer text>, <model updates>, "answer")`;
     - `GraphRecursionError`: trace `limit` with `steps=max_steps`, return
       `RunResult(LIMIT_MESSAGE.format(max_steps), max_steps, "limit")`;
     - any other exception (for example `fakes.ScriptExhausted` or `McpError`): trace `error` with
       `message=str(error)`, then raise it again.
2. **Tests** `tests/test_agent_graph.py`. No network. A module-scoped `McpTools` fixture with
   `notes_dir=<tmp>/notes` and `docs_dir=ROOT/"docs_corpus"`, as in `test_agent_hand.py`. Hand runs use
   `fakes.FakeModel`, graph runs `fakes.FakeChatModel`, both from the same script. Tests never compare the
   `write_note` `tool_result` content between hand and graph ("saved" vs "updated" depends on run order). Every new
   test function has a docstring. Cover:
   - **REQ-031 AC1:** `two_tool.json` through both agents, each with a `Trace` in `tmp_path`:
     - graph `stopped_by == "answer"`, `steps == 3`, and the same final text as hand;
     - the `tool_call` records give the same `(name, json.loads(arguments))` list for both;
     - `len(fake_chat.requests) == 3`.
   - **REQ-041 AC2:** the two traces have the same list of `kind` values.
   - **REQ-031 AC2:** a script of 6 `multiply {"a": 2, "b": 3}` calls with `max_steps=6`: `stopped_by == "limit"`,
     `text == LIMIT_MESSAGE.format(6)`, `steps == 6`, `len(fake_chat.requests) == 6`, 6 `tool_result` records, a
     `limit` record and no `final`. For the same script through hand, the `kind` lists are equal and the
     `RunResult` objects are equal. `max_steps=0` raises `ValueError`.
   - **Limit boundary:** 5 `multiply` calls then a text reply, with `max_steps=6`, gives `stopped_by == "answer"` and
     `steps == 6` in the graph.
   - **Tool errors, same text as hand:** a script `multiply {"x": 17, "b": 23}` then text gives
     `hand_content == graph_content == "error: missing argument 'a'; unknown argument 'x'"`.
   - **McpError:** with a closed `McpTools` (open then close a separate one), a graph run of one `multiply` call
     raises `McpError`, and the trace has an `error` record.
   - **Unknown tool (documented difference):** `divide {}` then text gives a graph `tool_result` whose content
     starts `Error: divide is not a valid tool`, with `is_error` true, and the run ends with `"answer"`.
   - **Adapter:** `as_langchain_tools` gives 9 tools with the MCP names; `multiply` invoked with
     `{"a": 17, "b": 23}` gives text with `float(text) == 391`.
   - **chat_model:** a `Settings` passed in directly (so `settings.load()` is not called) gives `model ==
     "openai/<model_name>"`, `api_base == "http://<host>:<port>/v1"`, `request_timeout == timeout_s`,
     `max_retries == 0`, and `model_kwargs["extra_body"] == {"chat_template_kwargs": {"enable_thinking": False}}`.
     Building it makes no network call. If `ChatLiteLLM` raises a `DeprecationWarning` under the test flags, stop
     and report it; do not weaken the flag.
   - **echo:** for AC1 the lines in order include `[node: model]`, `[node: tools]`, a line starting
     `[tool: multiply] 391`, and end with `[node: model]`.
   - **Model error:** a FakeChatModel with an empty script raises `fakes.ScriptExhausted` and the trace has an
     `error` record.
   - `Path(graph.__file__).read_text(encoding="utf-8")` contains neither `http://` nor `https://`.
   - Untested by design: `invalid_tool_calls` from a real model (known limit above).
