## Goal
A learner opens `viewer/viewer.html` in a browser, picks a trace file (for example from the `runs/` folder) with
the file picker, and steps through what the agent did: each event, its time and its full JSON, ending at the final
answer. The page works offline and makes no network requests.

## Acceptance criteria
1. **`viewer/viewer.html`**, one self-contained file (inline CSS and JS; no external URLs, fonts, images or
   frameworks). The CSP meta tag above is the first child of `<head>`. `<html lang="en">`,
   the document title `Agent Lab trace viewer`, plain short comments in the script (eli5).
   - **Layout** (an operating tool, calm and dense, not decorative):
     - a header row: the title, a file picker (`<label>` "Open a trace (.jsonl)" for an
       `<input type="file" accept=".jsonl">`), and a theme toggle `<button id="theme" aria-pressed="false|true">`
       whose text is always "Dark theme";
     - a summary row `id="summary"` with `aria-live="polite"`: `<n> events, <last t with 3 decimals> s` (for example
       `12 events, 0.004 s`) and the final text (the `text` of the last `final` record, else `No final answer`);
     - two panes side by side: on the left, `<ul id="events" aria-label="Events">`, one `<li>` per event, each with
       one `<button>` that shows the index from 1, the kind name as text, `t` with 3 decimals, and a one-line summary
       (`white-space: nowrap; overflow: hidden; text-overflow: ellipsis`). The summary is:
       - user, final: `text`;
       - model_reply: `text` when not empty, else `calls: ` plus the `tool_calls[].name` values joined by `, `;
       - tool_call, tool_result: `name`;
       - error: `message`;
       - model_request: `step ` plus `step`; limit: `steps ` plus `steps`;
       - a missing field gives an empty string.

       On the right, a detail pane: Previous and Next buttons, `#position` (`n / total`, `aria-live="polite"`),
       and the selected event as pretty JSON (2-space indent) in `<pre id="detail" tabindex="0"
       aria-label="Selected event">` with `white-space: pre-wrap; overflow-wrap: anywhere`;
     - at widths of 700 px and less the panes stack (list above detail); no horizontal page scroll at 360 px.
   - **Kinds** have distinct colours (a left border or label colour per kind), but the kind name is always shown
     as text, never by colour alone. Text contrast is at least 4.5:1 in both themes (checked by the orchestrator's
     screenshot review). `error` and `limit` read as problems; `final` reads as the answer.
   - **Behaviour:**
     - before a file is loaded, and for a file with 0 events: the panes show `Open a trace file from the runs
       folder.`, the summary shows `0 events, 0.000 s` and `No final answer`, `#position` is `0 / 0`, and Previous
       and Next are disabled;
     - loading reads the file with `file.text()`, removes a leading BOM (`﻿`), splits lines, skips empty
       lines, and parses each with `JSON.parse`. A line that fails to parse, parses to a non-object, or has no string
       `kind` is skipped and counted. When the count is above 0, `<p id="problems" role="alert">` says
       `1 line could not be read.` or `<N> lines could not be read.`; otherwise it is empty and hidden;
     - loading another file (or the same file again) replaces everything: new list, selection on event 1,
       `#problems` updated;
     - after a load the first event is selected; clicking an event selects it; Previous/Next move by one and are
       disabled at the ends;
     - keys: ArrowDown and ArrowRight select the next event, ArrowUp and ArrowLeft the previous one. They do nothing
       when the focus is in the file input or on `#theme`, or when Ctrl, Alt or Meta is held. `preventDefault` is
       called only when a key moves the selection. Selecting moves focus to the selected list button, sets
       `aria-current="true"` on it (and removes it from all others), and scrolls it into view;
     - all controls show a visible focus ring (`:focus-visible`, at least 2 px);
     - the theme starts from `prefers-color-scheme`; the toggle switches `data-theme` on `<html>` between `light`
       and `dark` and updates `aria-pressed`.
   - Trace data is rendered with `textContent` only, never `innerHTML`, because traces contain model text.
   - No size limit is set; the viewer is tested with the 12-line fixture only.
2. **Fixture** `tests/fixtures/trace_two_tool.jsonl`: generated once from a fake hand run of `two_tool.json` (for
   example with `hand.run`, `FakeModel`, `McpTools` and `Trace` in a short script, not committed) and committed as a
   static file; the tests never regenerate it. 12 lines in this order: user, model_request, model_reply,
   tool_call, tool_result, model_request, model_reply, tool_call, tool_result, model_request, model_reply, final.
   Its final text is `The answer is 391. I saved it as the note "result".` UTF-8, LF, no machine paths or user
   names.
3. **Tests** `tests/test_viewer.py` (every test has a docstring; Playwright sync API; a module-scoped fixture that
   starts Playwright and `p.chromium.launch(channel="chrome", headless=True)` and at teardown calls
   `browser.close()` and `playwright.stop()`; a function-scoped page fixture that calls `page.close()`; the page
   opened with `Path(...).as_uri()`; no `time.sleep`, waits only with `expect(...)` or `wait_for_function`, timeout
   5 s; a missing Chrome makes the tests fail, never skip; the file runs in under 15 s):
   - **fixture check (no browser):** the fixture has 12 lines; each parses with `t` and `kind`; `t` never
     decreases; the kinds are in the order above;
   - **page script ran:** after `goto`, `#events` exists and the empty-state text is shown; `#position` is `0 / 0`;
   - **REQ-042 AC1:** set the fixture on the file input; `#events li` count is 12; `#summary` contains `12 events`
     and the final text; `#position` is `1 / 12`;
   - **keys:** `page.locator("#events li button").first.focus()`, then ArrowDown twice gives `#position` `3 / 12`
     and `#detail` contains `"kind": "model_reply"`; ArrowUp gives `2 / 12`; after each move exactly one button has
     `aria-current="true"`; Previous is disabled on event 1 and Next on event 12;
   - **theme:** the toggle changes `data-theme` and `aria-pressed`, and its text stays `Dark theme`;
   - **bad lines:** a file written in `tmp_path` with 2 good lines, one line `not json` and one line `5` shows
     `#problems` with `2 lines could not be read.` and lists 2 events; then loading the fixture shows 12 events
     and an empty `#problems`;
   - **text is not HTML:** a file in `tmp_path` whose `final` text is `<img src=x onerror=alert(1)>` shows that text
     literally, the page has no `img` element, and `page.on("dialog")` records no dialog;
   - **zero network requests:** record `page.on("request")` and `page.on("requestfailed")` from before `goto`;
     load the page and the fixture and step through all 12 events; every request URL starts with `file:` or
     `data:`, and no request failed. The HTML source matches neither `re.search(r"(?i)https?://|//[a-z]", html)`;
     and `page.evaluate("fetch('http://127.0.0.1:9/').then(() => 'fetched', () => 'blocked')")` returns `blocked`;
   - **layout:** at 360 px wide (with the fixture loaded), `document.documentElement.scrollWidth <= 360`; at
     700 px the bottom of `#events` is at or above the top of `#detail`; at 1000 px the left of `#detail` is
     greater than the right of `#events`.
4. **Full suite.** `.venv\Scripts\python.exe -m pytest -rs -W error::DeprecationWarning` passes with 0 skipped and 0
   failed; `passed` is at least 170 (MEASURED after F-015) plus the number of new test items in
   `tests/test_viewer.py`.

5. **Round 2 (orchestrator design review, 2026-10-31):**
   - The round-1 fixture is invented (every `t` is 0, the user text is not the canonical question, the multiply
     result is `391`, but the real server returns `391.0`). Replace it with a real trace: run this once from the
     workspace and copy the produced file to `tests/fixtures/trace_two_tool.jsonl` (do not commit the script):
     ```
     import tempfile
     from pathlib import Path
     from agent_lab import fakes, settings
     from agent_lab.agent import hand
     from agent_lab.mcp_client import McpTools
     from agent_lab.trace import Trace
     tmp = Path(tempfile.mkdtemp())
     config = settings.Settings(notes_dir=str(tmp / "notes"), docs_dir="docs_corpus")
     with McpTools(settings=config) as tools, Trace.new(tmp / "runs", "hand") as log:
         hand.run("What is 17 times 23? Save the answer as a note called result.",
                  model=fakes.FakeModel(fakes.builtin("two_tool")), tools=tools, trace=log)
     print(log.path)
     ```
     The fixture check test also asserts the first line's `text` is the canonical question above and the last line's
     `t` is greater than 0. Update other test expectations that used the invented values.
   - The theme toggle's pressed state is visible: with `aria-pressed="true"` it has a filled background (accent
     colour) and contrasting text; the label text stays `Dark theme`.
   - Above 700 px wide, the detail pane is `position: sticky; top: 16px` with a `max-height` of the viewport minus
     32 px and its own scroll, so it stays in view while the list scrolls.
   - `#detail` uses a font size of at least 13 px.
