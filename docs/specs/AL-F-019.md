## Acceptance criteria
1. **`tests/test_live.py`**. Every test has a docstring. All tests are `@pytest.mark.live` except
   `test_attempts_helper` (the only offline test in the file).
   - `QUESTION = "What is 17 times 23? Save the answer as a note called result."`.
   - **Fixture `live_server`** (module scope, `yield` inside `try/finally`): `monkeypatch.chdir(ROOT)` through
     `pytest.MonkeyPatch().context()`; `config = settings.load(ROOT / "agent-lab.toml")`, failing (not skipping)
     with a clear message if the file is missing. If the port is free: `home` is a `tmp_path_factory` folder,
     `start(config, home)` must return 0, `owned = True`. If the port is in use: `home = ROOT / ".agent-lab"`,
     `owned = False`, and the fixture fails with `server on port <port> was not started by 'agent-lab model start'
     from the repo root (no .agent-lab/model.pid)` when that pid file is missing. Then one warm-up `model.chat`
     call. It yields `(config, home, owned)`. Teardown calls `stop(config, home)` only when `owned` is true, also
     after test failures.
   - **Helper `attempts(fn, n=3)`**: `fn()` returns `None` on success and raises on failure. `AttemptError(message,
     reply=None, trace_path=None)` is the error to raise. `attempts` returns the 1-based number `k` of the first
     success and prints `passed on attempt {k} of {n}`. After `n` failures it calls `pytest.fail` with one line per
     attempt (`attempt i: <error text>`), then `last model reply: <reply or none>`, then
     `trace: <trace path or none>`, from the last error.
   - **`test_attempts_helper`** (offline): a function failing once then passing gives 2; a function always failing
     makes `attempts` fail with text containing `attempt 3:` and `trace: t.jsonl` (use `pytest.raises` on
     `pytest.fail.Exception`).
   - **REQ-051 lessons** (parametrized: `01_model_call`, `02_tool_call`, `03_structured_output`, `04_agent_loop`,
     `05_mcp_client`, `06_langgraph_agent`). Each attempt uses a fresh subfolder of `tmp_path` and runs
     `subprocess.run([sys.executable, "lessons/<name>.py"], cwd=ROOT, env={**os.environ, "PYTHONPATH": "src",
     "PYTHONUTF8": "1", "AGENT_LAB_NOTES_DIR": <sub>/notes, "AGENT_LAB_RUNS_DIR": <sub>/runs}, capture_output=True,
     text=True, encoding="utf-8", timeout=30)`. Success is exit code 0. `TimeoutExpired` or another exit code is a
     failed attempt: the message has the exit code (or `timed out after 30 s`) and the last 500 characters of
     stderr; `reply` is the last 500 characters of stdout; `trace_path` is the newest file in `<sub>/runs` or
     `None`.
   - **REQ-051 agents** (parametrized: `hand`, `graph`). Each attempt uses a fresh subfolder of `tmp_path`:
     `with McpTools(settings=dataclasses.replace(config, notes_dir=str(<sub>/"notes"))) as tools,
     Trace.new(<sub>/"runs", engine) as log:` run `hand.run(QUESTION, model=model, tools=tools, trace=log)` or
     `graph.run(QUESTION, model=graph.chat_model(config), tools=tools, trace=log)`. After the `with` block closes,
     read the trace with `json.loads` per line. Success needs all of:
     - `stopped_by == "answer"` and `"391" in text`;
     - the first `tool_call` record has `name == "multiply"` and `json.loads(arguments) == {"a": 17, "b": 23}`;
     - a later `tool_call` record has `name == "write_note"`, and its arguments have `name == "result"` and a
       `text` containing `391`;
     - the attempt took at most 30 s (`time.monotonic()`, checked after the call returns; a hung call is bounded by
       `timeout_s`).
     On failure, `reply` is the last `model_reply` text in the trace and `trace_path` is `log.path`.
   - **REQ-054 AC2**: find the single table line in `docs/DEPENDENCIES.md` whose first cell equals
     `Path(config.model).name`; its last cell must match `[0-9a-f]{64}`; fail clearly if there is no such row or more
     than one. Compare with `hashlib.sha256` of `Path(config.model)` read in 1 MiB blocks. No 30 s limit.
   - **REQ-003 AC6**, defined last in the file, body in `try/finally`, using the fixture's `home`: `stop` returns 0,
     then `status` prints `stopped`; `start` returns 0, then `status` prints `running`; then one warm-up `model.chat`
     call. Compare the last printed line each time (`capsys`, `strip().splitlines()[-1]`). The 30 s limit does not
     apply to `start`, `stop` or the warm-up. When the server was started by the human, this restarts it in the same
     `ROOT/.agent-lab` home (new pid in the same pid file), and it stays running afterwards.

4. **Round 2 (orchestrator live run, 2026-10-31).**
   - MEASURED: `test_live_server_restart` failed: `start` returned 1 ("port 8090 is in use") right after `stop`
     returned 0, because `stop` returns as soon as `taskkill` succeeds, before Windows frees the port. The same
     happens with `agent-lab model stop` then `agent-lab model start`.
   - Fix in `model_server.stop`: after a successful `_kill`, wait until `port_in_use(settings)` is false, checking
     every 0.25 s for up to 10 s, then delete the pid file and print `stopped`. If the port is still in use after
     10 s, print `stopped, but port <port> is still in use` and return 0. A short teaching comment says why.
   - Unit tests in `tests/test_model_server.py` (offline; patch `_kill`, `pid_alive`, `port_in_use` and
     `time.sleep`): `stop` waits until the port is free (port in use for 2 checks, then free: `stopped`, 3
     `port_in_use` calls); a port that stays in use ends with the `still in use` line and returns 0 without sleeping
     for real.
   - MEASURED: the round-1 gate ran the live tests inside the Codex run, started the real GPU server and left it
     running with no pid file (an orphan the orchestrator stopped). From round 2 the gate runs only the offline
     command below. Do not run `-m live` inside the Codex run.
