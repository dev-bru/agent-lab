## Goal
The heart of Agent Lab: an agent written by hand, so a learner can read every line of the loop. It asks the model,
runs the tools the model asks for (through the real MCP server), feeds the results back, and stops on an answer or
at the step limit. Every step is written to a trace file.

## Facts (DOCUMENTED, fastmcp 4.1.4 source, read 2026-10-30 by the spec auditor)
- With `keep_alive=False`, leaving the client disconnects; the MCP stdio layer closes stdin, waits about 2 s, then
  kills the child tree (a Windows job object).
- `call_tool(name, arguments, *, raise_on_error, timeout, ...)` returns a result with `is_error`, `content` and
  `structured_content`.
- The test network guard does not affect pipes or the event loop's loopback socket pair. The child does not
  inherit it.
- MEASURED earlier (F-008): `agent_lab` is installed editable in `.venv`, so `python -m agent_lab.mcp_server`
  works from any folder.

## Acceptance criteria
1. **`agent_lab.mcp_client`**: `class McpError(RuntimeError)` and `class McpTools`, a synchronous wrapper around one
   open FastMCP stdio session.
   - `McpTools(module="agent_lab.mcp_server", settings=None)`, with `settings` defaulting to `settings.load()`.
     `timeout_s` from settings is used as the tool-call timeout too.
   - **Open** (`open()`, also called by `__enter__`):
     - start one `daemon=True` thread that runs `asyncio.run(self._main())` once;
     - `_main` does, inside ONE task: `async with Client(transport, mode="legacy") as client`, then
       `self._tools = await client.list_tools()`, then sets a `threading.Event` (ready), then
       `await self._stop.wait()` (an `asyncio.Event` created inside `_main`). Enter and exit happen in the same
       task;
     - `transport = StdioTransport(command=sys.executable, args=["-m", module], env=env, cwd=os.getcwd(),
       keep_alive=False, log_file=Path(os.devnull))`. If FastMCP rejects `log_file=Path(os.devnull)`, leave the
       default and say so in a comment;
     - `env = {**os.environ, "AGENT_LAB_NOTES_DIR": str(Path(settings.notes_dir).resolve()),
       "AGENT_LAB_DOCS_DIR": str(Path(settings.docs_dir).resolve())}`;
     - the caller waits for ready with `timeout_s`. If `_main` fails (for example a bad module), or ready does not
       come in time, `open()` stops everything, joins the thread and raises
       `McpError("MCP server did not start: <reason>")`. No thread or child is left behind.
     - Round 2: if any `BaseException` that is not an `Exception` (for example `KeyboardInterrupt` from Ctrl+C)
       arrives while `open()` waits, `open()` calls `close()` and raises it again unchanged. So `with McpTools()`
       interrupted during start leaves no thread or child.
   - `specs() -> list[dict]` returns `[tools_schema.to_openai(t) for t in self._tools]`, built once and returned
     as the same list (read-only by contract). `schema(name)` returns that tool's `input_schema` or `None`.
     `names()` returns the sorted names.
   - `call(name, args) -> tuple[str, bool]`:
     - a closed session raises `McpError("session is closed")`;
     - run `client.call_tool(name, args, raise_on_error=False, timeout=timeout_s)` with
       `asyncio.run_coroutine_threadsafe` and wait `future.result(timeout=timeout_s + 5)`;
     - on a timeout, cancellation or a dead session (`TimeoutError`, `concurrent.futures.TimeoutError`,
       `concurrent.futures.CancelledError`, or any exception from the session), call `future.cancel()` and raise
       `McpError("tool call failed: <reason>")`. Round 2: on a `BaseException` that is not an `Exception`, call
       `future.cancel()` and raise it again unchanged;
     - the text is `"\n".join(c.text for c in result.content if hasattr(c, "text"))`. If that is empty and
       `result.structured_content` is not `None`, it is `json.dumps(value)`, where `value` is
       `structured_content["result"]` when `structured_content` is a dict whose only key is `"result"` (FastMCP
       wraps non-object returns this way, so `list_notes` gives `[]`), else `structured_content`. Otherwise it is
       `""`;
     - return `(text, bool(result.is_error))`.
   - **Close** (`close()`, also called by `__exit__`):
     - it runs once (a `_closed` flag); later calls do nothing;
     - it calls `loop.call_soon_threadsafe(stop.set)`, then `thread.join(10)`;
     - if the thread is still alive, it raises `McpError("MCP server did not stop")`;
     - there is no `__del__`, because a finalizer that joins a thread can hang at exit.
2. **`agent_lab.trace`**:
   - `KINDS = ("user", "model_request", "model_reply", "tool_call", "tool_result", "error", "final", "limit")`.
   - `Trace(path)` opens `path` in append mode (UTF-8, `errors="backslashreplace"`, round 2: so a lone surrogate
     such as `"\ud800"` in model text is written as `\ud800` and never raises) and records `time.monotonic()`.
     - `write(kind, **fields)`: an unknown kind raises `ValueError`. Otherwise it writes one line
       `json.dumps({"t": round(time.monotonic() - start, 3), "kind": kind, **fields}, ensure_ascii=False,
       default=str)` and flushes.
     - `close()` closes the file. `Trace` is a context manager.
   - `Trace.new(runs_dir, engine)`:
     - `engine` must match `^[a-z]+$`, else `ValueError`;
     - create the folder;
     - the name is `<YYYYMMDDTHHMMSS_mmm>-<engine>.jsonl` from `datetime.now(timezone.utc)` (the module does
       `from datetime import datetime, timezone`);
     - claim the name with `open(path, "x")`, trying `-2`, `-3`, ... on `FileExistsError` only;
     - close that handle and return `Trace(path)`, which appends (safe, because the name is claimed);
     - `trace.path` is the path.
3. **`agent_lab.agent`** (`__init__.py`):
   - `LIMIT_MESSAGE = "Stopped: reached the step limit ({} model calls)."`;
   - `@dataclass(frozen=True) class RunResult` with `text: str`, `steps: int` and `stopped_by: str` (`"answer"` or
     `"limit"`);
   - `SYSTEM_PROMPT = "You are a helpful assistant. Use the tools when they help. Answer briefly."`.
4. **`agent_lab.agent.hand.run(question, *, model, tools, trace=None, max_steps=6, echo=None) -> RunResult`**.
   - `model` has `.chat(messages, tools=...)`. `tools` has `specs()`, `schema(name)`, `names()` and
     `call(name, args)`. `echo` is an optional `Callable[[str], None]`.
   - `max_steps < 1` raises `ValueError`.
   - `run()` never closes `trace`; the caller does. Each part of the loop has a short teaching comment.
   - Steps:
     1. `history = [{"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": question}]`; trace
        `user` with `text`.
     2. For `step` in `1..max_steps`:
        - echo `[step <step>/<max_steps>]`;
        - trace `model_request` with `step` and `messages` (the count);
        - call `reply = model.chat(history, tools=tools.specs())`. A `ModelError` is traced as `error` with
          `message`, then raised again;
        - trace `model_reply` with `text` and `tool_calls` (a list of `{id, name, arguments}`, where `arguments` is
          the raw string);
        - with no tool calls: trace `final` with `text`, then return `RunResult(reply.text or "", step, "answer")`;
        - otherwise append the assistant message (`content` is `reply.text or ""`, and `tool_calls` are in OpenAI
          form as in lesson 02);
        - for each call in order:
          - trace `tool_call` with `id`, `name` and `arguments` (the raw string);
          - work out the problems, checking in this order:
            1. blank or whitespace `arguments` means `{}`; otherwise `json.loads`, and a failure gives
               `arguments are not valid JSON`. Round 2: `arguments` that is not a `str` (for example `None`) also
               gives `arguments are not valid JSON`, never an exception;
            2. `tools.schema(name) is None` gives `unknown tool '<name>'; valid tools: <", ".join(tools.names())>`;
            3. otherwise `tools_schema.check_args(schema, args)`;
          - with problems, `content = "error: " + "; ".join(problems)`;
          - otherwise `text, is_error = tools.call(name, args)` and `content = "error: " + text if is_error else
            text`;
          - trace `tool_result` with `id`, `name`, `content` and `is_error`;
          - echo `[tool: <name>] <content>` (in full);
          - append `{"role": "tool", "tool_call_id": id, "content": content}`.
     3. The tool calls of the last allowed reply are still run and traced. Then trace `{"kind": "limit", "steps":
        max_steps}` (no `final`) and return `RunResult(LIMIT_MESSAGE.format(max_steps), max_steps, "limit")`.
   - `McpError` from `tools.call` (for example the server died) is not caught. It reaches the caller.
5. **Plain English and local only.** The existing REQ-052 docstring test and the no-URL checks pass for the new
   modules.
